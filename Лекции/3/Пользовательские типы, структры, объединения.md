### Зачем разделять программу на файлы

В небольшом учебном примере один файл ещё можно прочитать сверху вниз. В приложении с обработкой заказов удобнее отделить интерфейс расчёта цены от его реализации и от кода пользовательского интерфейса. Тогда изменение формулы не заставляет искать нужную функцию среди сотен несвязанных строк, а зависимые части видят только обещанный контракт.

При сборке каждый `.cpp` проходит компиляцию как отдельная единица трансляции. Заголовок сообщает, какие имена и сигнатуры доступны, а определение предоставляет сам код. Если объявления расходятся, проблема проявится либо при проверке типов, либо позже, когда линковщик не найдёт ожидаемое определение.

Один огромный файл удобен ровно до того момента, когда поиск функции превращается в экскурсию с провожатым.

Пока программа помещается на одном экране, один `.cpp` кажется удобным. Но с ростом проекта нам потребуется отделять интерфейс модуля от его реализации и собирать несколько единиц трансляции.

Пусть модуль `utils` предоставляет две функции. В заголовке находятся объявления:

```cpp
// utils.h
#ifndef UTILS_H
#define UTILS_H

#include <string>

namespace utils {
std::string hello();
std::string world();
}

#endif
```

В `.cpp` располагаются определения:

```cpp
// utils.cpp
#include "utils.h"

std::string utils::hello() {
    return "hello";
}

std::string utils::world() {
    return "world";
}
```

А использующий файл подключает интерфейс:

```cpp
// main.cpp
#include "utils.h"
#include <iostream>

int main() {
    std::cout << utils::hello() << ' ' << utils::world() << '\n';
}
```

Собрать программу GCC можно так:

```bash
g++ main.cpp utils.cpp -std=c++17 -Wall -Wextra -o app
```

Каждый `.cpp` после препроцессинга компилируется как отдельная единица трансляции, затем объектные файлы соединяет компоновщик. Заголовок обычно не компилируется как самостоятельный модуль: его текст включается директивой `#include`.

### Защита заголовка

Если один заголовок попал в единицу трансляции несколькими путями, повторные определения могут вызвать ошибку. Include guard разрешает содержимое только при первом включении:

```cpp
#ifndef UTILS_H
#define UTILS_H

// объявления

#endif
```

Распространена и директива `#pragma once`. Она поддерживается основными компиляторами, но include guard состоит из стандартных директив препроцессора и не зависит от расширения.

> Защита предотвращает повторное включение в пределах одной единицы трансляции. Она не исправляет нарушение правила одного определения между разными единицами трансляции.

### Пространства имён

Жизненный пример здесь почти буквальный: в компании может быть два сотрудника с именем Алексей, но сочетание отдела и имени уже позволяет понять, о ком идёт речь. Пространство имён добавляет такой контекст идентификатору. `graphics::Point` и `geometry::Point` могут иметь одинаковую короткую часть, оставаясь разными типами.

Квалифицированное имя делает выбор явным в месте использования. Директива `using namespace` расширяет набор кандидатов, которые компилятор рассматривает без квалификатора, поэтому удобство может обернуться неоднозначностью. Особенно нежелательно навязывать это решение всем включающим файлам через заголовок.

`using namespace std;` экономит несколько символов, а затем иногда тратит целую лекцию на объяснение столкновения имён.

**Пространство имён** группирует имена и помогает избежать конфликтов:

```cpp
namespace geometry {
struct Point {
    double x;
    double y;
};

double distance(Point first, Point second);
}
```

Полное имя отделяется оператором разрешения области `::`:

```cpp
geometry::Point origin{0.0, 0.0};
```

Пространства можно вкладывать, а начиная с C++17 записывать короче:

```cpp
namespace course::geometry {
// ...
}
```

### Директивы и объявления `using`

Директива открывает все имена пространства для неквалифицированного поиска:

```cpp
using namespace geometry;
```

Объявление вводит одно выбранное имя:

```cpp
using geometry::Point;
```

Второй вариант локальнее и лучше показывает зависимость. `using namespace` особенно нежелателен в заголовке: он влияет на каждый файл, который этот заголовок подключит.

### Нулевой указатель

Для указателя, который сейчас ни на что не указывает, в современном C++ используется `nullptr`:

```cpp
int* value{nullptr};

if (value == nullptr) {
    value = new int{42};
}

delete value;
```

Макрос `NULL` и литерал `0` исторически применялись как нулевые константы указателя, но могут вести себя как целые числа при перегрузке. `nullptr` имеет отдельный тип `std::nullptr_t` и точнее выражает намерение.

### Перечисления

Перечисление подходит для закрытого набора состояний: например, заказ может быть создан, оплачен, отправлен или отменён. В отличие от произвольного числа, значение перечисления несёт смысл непосредственно в типе. Компилятор помогает не перепутать состояние заказа с кодом ошибки или номером месяца.

При разборе примера важно увидеть два уровня. Объект перечисления хранит одно из допустимых значений, а условная конструкция выбирает действие по этому значению. `enum class` дополнительно не выпускает имена элементов в окружающую область и не допускает неявного смешения с целыми числами.

Число `3` может означать что угодно; `OrderStatus::shipped` хотя бы не заставляет читать древние комментарии.

Перечисление создаёт тип с конечным набором именованных значений:

```cpp
enum Status {
    success,
    failure,
    warning
};
```

Обычное `enum` помещает имена перечислителей в окружающую область и допускает неявное преобразование в целое число. Это удобно для совместимости со старым кодом, но повышает риск конфликтов.

`enum class` сохраняет имена внутри типа и запрещает случайное неявное преобразование:

```cpp
enum class Status {
    success,
    failure,
    warning
};

Status current{Status::success};
```

Базовый тип можно указать явно:

```cpp
enum class Status : unsigned char {
    success,
    failure,
    warning
};
```

Для вывода лучше определить содержательное представление, а не показывать случайный номер:

```cpp
std::ostream& operator<<(std::ostream& output, Status status) {
    switch (status) {
        case Status::success: return output << "success";
        case Status::failure: return output << "failure";
        case Status::warning: return output << "warning";
    }
    return output << "unknown";
}
```

### Структуры

**Структура** объединяет связанные данные в новый тип:

```cpp
struct Date {
    int day;
    int month;
    int year;
};

struct Person {
    std::string name;
    Date birth;
};
```

Объект можно агрегатно инициализировать:

```cpp
Person student{"Михаил", {10, 3, 1998}};
std::cout << student.name << '\n';
```

Оператор `.` обращается к члену объекта, `->` — к члену через указатель:

```cpp
void printDate(const Date& date) {
    std::cout << date.day << '.' << date.month << '.' << date.year;
}

void printDate(const Date* date) {
    if (date != nullptr) {
        std::cout << date->day << '.' << date->month << '.' << date->year;
    }
}
```

Структура в C++ может иметь методы, конструкторы, наследование и другие возможности класса. Главное языковое различие: у `struct` доступ и наследование по умолчанию `public`, у `class` — `private`. По договорённости структуры часто оставляют простыми агрегатами данных.

### Размещение полей, выравнивание и padding

Представим шкаф с полками разной высоты. Чтобы крупные коробки начинались в удобных позициях, между ними иногда остаётся свободное место. Компилятор делает похожее при размещении полей: добавляет промежутки для соблюдения требований выравнивания и может добавить хвостовой padding, чтобы элементы массива структур располагались корректно.

Порядок полей способен изменить размер объекта, однако точные смещения зависят от реализации и целевой платформы. Поэтому пример со `sizeof` показывает наблюдение для конкретной сборки, а не универсальную схему расположения каждого байта.

Padding — это редкий случай, когда пустое место официально считается частью результата работы.

Поля располагаются в порядке объявления, но между ними и после последнего поля реализация может добавить **отступы** для соблюдения выравнивания. Поэтому размер структуры не обязан равняться простой сумме `sizeof` её полей.

```cpp
struct Example {
    char marker;
    int count;
    double value;
};

std::cout << sizeof(Example) << '\n';
std::cout << alignof(Example) << '\n';
```

Точные значения зависят от платформы и ABI. Перестановка полей иногда уменьшает размер, но менять логичную структуру данных ради нескольких байтов без измерений не стоит.

### Объединения

`union` предоставляет общую область хранения для нескольких членов:

```cpp
union Number {
    int integer;
    double real;
};
```

В каждый момент активен один член. Запись в другой член меняет активный объект. Чтение неактивного члена в общем случае не является безопасным способом преобразования представления.

Объединения требуют ручного контроля активного типа и времени жизни сложных членов. Поэтому в прикладном коде чаще используют безопасные библиотечные типы.

### `std::variant` и `std::optional`

`std::variant` хранит одно значение из перечисленного набора типов и помнит активный вариант:

```cpp
#include <variant>

std::variant<int, std::string> value{42};
value = std::string{"answer"};
std::cout << std::get<std::string>(value) << '\n';
```

`std::optional<T>` выражает наличие или отсутствие значения одного типа:

```cpp
#include <optional>

std::optional<int> findAnswer(bool found) {
    if (found) {
        return 42;
    }
    return std::nullopt;
}
```

Это разные задачи: `variant` выбирает тип, `optional` — наличие значения.

### Псевдонимы типов

Псевдоним даёт существующему типу другое имя:

```cpp
using StudentId = unsigned long long;
using Callback = void (*)(int);
```

Старый синтаксис `typedef` остаётся допустимым, но `using` читается слева направо и удобнее работает с шаблонами.

Псевдоним не создаёт новый отдельный тип. `StudentId` выше остаётся тем же типом, что и `unsigned long long`.

### Что означает `inline`

Исторически `inline` связывали с просьбой встроить тело функции вместо вызова. Современный компилятор принимает решение о встраивании независимо от ключевого слова.

Важная языковая роль `inline` — разрешить одинаковое определение функции или переменной в нескольких единицах трансляции при соблюдении правила одного определения. Поэтому функции, определённые внутри класса, и шаблоны можно размещать в заголовках.

```cpp
inline int square(int value) {
    return value * value;
}
```

### Аргументы по умолчанию

```cpp
void printLine(char symbol = '-', int count = 20);

printLine();
printLine('=');
printLine('*', 10);
```

После параметра со значением по умолчанию все следующие параметры в этой области объявления тоже должны иметь значения по умолчанию. Обычно значение указывают один раз в объявлении интерфейса, а в определении не повторяют.

Значение подставляется в месте вызова. Поэтому изменение значения по умолчанию требует перекомпиляции вызывающего кода.

### Перегрузка функций

Когда компилятор встречает вызов, он собирает доступные функции с нужным именем, проверяет число аргументов и оценивает допустимые преобразования типов. Затем выбирается лучший подходящий кандидат. Если лучших несколько или нет ни одного, программа не проходит компиляцию.

Практически перегрузки позволяют сохранить одно действие под одним именем: например, `print` может принимать число, строку или пользовательский объект. Но набор должен оставаться понятным. Если смысл функций различается, общее имя скрывает различие вместо упрощения интерфейса.

Перегрузка хороша, пока компилятор выбирает функцию быстрее, чем программист угадывает, какую именно он выбрал.

Несколько функций могут иметь одно имя, если различаются списки параметров:

```cpp
int area(int side);
int area(int width, int height);
double area(double radius);
```

Компилятор выбирает перегрузку по аргументам и допустимым преобразованиям. Только возвращаемого типа для различия недостаточно:

```cpp
int value();
// double value(); // недопустимая перегрузка
```

Значения по умолчанию способны сделать вызов неоднозначным, поэтому их нужно проектировать вместе со всем набором перегрузок.

### Указатели на функции

Функция тоже имеет адрес. Указатель должен точно соответствовать её типу:

```cpp
int add(int left, int right) {
    return left + right;
}

using Operation = int (*)(int, int);
Operation operation{&add};

std::cout << operation(2, 3) << '\n';
```

Символ `&` при инициализации и `*` при вызове можно опустить, но явная форма иногда помогает увидеть смысл.

Указатели на функции применяются для обратных вызовов и выбора поведения. В современном C++ рядом с ними существуют функциональные объекты, лямбда-выражения и `std::function`; к ним мы вернёмся позже.

### Итоги

Разделение на заголовок и реализацию помогает управлять большим проектом, пространства имён защищают имена, а пользовательские типы позволяют говорить в коде терминами предметной области. При этом удобная конструкция не отменяет правил памяти: структура может содержать padding, `union` требует контроля активного члена, а указатель на функцию обязан точно соответствовать сигнатуре.
