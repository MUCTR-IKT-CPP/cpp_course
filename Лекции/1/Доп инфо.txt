Отлично, давай разберём глубже **этапы 2–5** компиляции C++:

---

## **2) Разбор и семантика (Front-End)**

🔹 **Что происходит:**

* Препроцессированный код поступает в **лексический анализатор (lexer)** → преобразует поток символов в токены (ключевые слова, идентификаторы, литералы, операторы).
* **Парсер** строит синтаксическое дерево (AST — Abstract Syntax Tree).
* Проводится **семантический анализ**:

  * проверка типов (int нельзя присвоить в std::string),
  * правильность вызова функций,
  * область видимости переменных,
  * поиск конфликтов имён (name lookup, ADL — argument-dependent lookup).

🔹 **Особенности C++:**

* **Шаблоны (templates):**

  * Проверяются при первом использовании (instantiation).
  * Two-phase lookup: сначала проверяется синтаксис, потом конкретизация при подстановке типов.
* **constexpr/consteval:** некоторые выражения вычисляются прямо на этапе компиляции.
* **Concepts (C++20):** компилятор может сразу отсеять неподходящие типы при инстанцировании шаблонов.

📌 На выходе: **AST (дерево разбора)** + таблицы символов.

---

## **3) Промежуточное представление (IR)**

🔹 **Что происходит:**

* AST преобразуется во внутреннее представление.
* В GCC это GIMPLE, в Clang/LLVM — LLVM IR.

🔹 **Зачем:**

* IR абстрагирует код от конкретного процессора.
* Удобнее применять оптимизации, чем работать напрямую с AST или ассемблером.

🔹 **Примеры:**

```cpp
int sum(int a, int b) { return a + b; }
```

В LLVM IR:

```llvm
define i32 @sum(i32 %a, i32 %b) {
  %1 = add i32 %a, %b
  ret i32 %1
}
```

📌 На выходе: **IR-код**.

---

## **4) Оптимизации (Middle-End)**

🔹 **Что происходит:**
Компилятор применяет множество оптимизаций:

* **Constant folding** — `2+2` сразу превращается в `4`.
* **Inline expansion** — подстановка тела функции вместо вызова (если выгодно).
* **Dead code elimination** — удаляется неиспользуемый код.
* **Loop optimizations** — разворачивание циклов (loop unrolling), перенос инвариантов за цикл.
* **Common subexpression elimination** — `x*y` вычисляется один раз, если повторяется.

🔹 **Уровни оптимизации (`-O0`, `-O1`, `-O2`, `-O3`, `-Ofast`, `-Os`):**

* `-O0` → без оптимизаций (удобно для отладки).
* `-O2` → баланс скорость/размер.
* `-O3` → максимальная агрессивность.
* `-Ofast` → отключает строгость стандарта (может ломать IEEE 754, UB).
* `-Os` → оптимизация по размеру.

📌 На выходе: **оптимизированный IR**.

---

## **5) Генерация кода (Back-End)**

🔹 **Что происходит:**

* IR транслируется в **машинно-зависимый ассемблер**.
* Используется **регистровый аллокатор** (решает, какие переменные хранить в регистрах, а какие в памяти).
* Применяются низкоуровневые оптимизации:

  * выбор конкретных инструкций (instruction selection),
  * переупорядочивание инструкций для конвейера процессора,
  * устранение задержек загрузки (load delay slots).

🔹 **Пример:**
Тот же `sum(int a, int b)` → x86-64 ассемблер:

```asm
sum:
    mov eax, edi
    add eax, esi
    ret
```

📌 На выходе: **.s (файл с ассемблерным кодом)**.

---

👉 Итого:

* **2) Front-End** → AST, семантика.
* **3) IR** → промежуточный код, независимый от архитектуры.
* **4) Optimizer** → оптимизация IR.
* **5) Back-End** → ассемблер под конкретное железо.

# 🔧 Этап оптимизации (Middle-End)

## 🎯 Цель

* Ускорить выполнение программы.
* Снизить размер кода.
* Уменьшить энергопотребление (актуально для embedded/мобилок).
* Но **не менять семантику** (за исключением «агрессивных» режимов, типа `-Ofast`).

---

## 📌 Основные виды оптимизаций

### 1. **Constant folding / propagation**

* Вычисление констант на этапе компиляции.

```cpp
int x = 2 * 3;  // превращается в int x = 6;
```

### 2. **Dead code elimination (DCE)**

* Удаляется код, на результат не влияющий.

```cpp
if (false) { foo(); } // полностью вырезается
```

### 3. **Inlining**

* Подстановка тела функции вместо вызова.
* Ускоряет работу (меньше вызовов), но увеличивает размер бинарника.

```cpp
inline int square(int x) { return x*x; }
```

### 4. **Loop optimizations**

* **Loop unrolling** — разворачивание цикла для уменьшения накладных расходов:

```cpp
for (int i=0; i<4; i++) sum += a[i];
// может стать
sum += a[0] + a[1] + a[2] + a[3];
```

* **Loop fusion** — объединение двух циклов в один.
* **Loop invariant code motion** — вынесение вычислений за пределы цикла.

### 5. **Common subexpression elimination (CSE)**

* Если выражение повторяется и не меняется, оно вычисляется один раз.

```cpp
int z = (x*y) + (x*y);  // оптимизируется в int tmp=x*y; int z=tmp+tmp;
```

### 6. **Strength reduction**

* Замена дорогих операций на дешёвые.

```cpp
for (int i=0; i<n; i++) arr[i*2] = ...;
// компилятор превратит i*2 в i<<1
```

### 7. **Register allocation**

* Переменные по максимуму держатся в регистрах процессора (быстрее, чем память).

### 8. **Instruction scheduling**

* Переупорядочивание инструкций для оптимального использования конвейера CPU.

### 9. **Tail call optimization (TCO)**

* Оптимизация хвостовой рекурсии:

```cpp
int f(int n, int acc=1) { return n==0 ? acc : f(n-1, acc*n); }
// может быть переписано в цикл → без роста стека
```

### 10. **Interprocedural optimizations (IPO)**

* Компилятор анализирует не только функцию, но и соседние единицы трансляции.
* Примеры: **inline across modules**, удаление неиспользуемых функций.

---

## 📊 Уровни оптимизации (GCC/Clang)

* `-O0` — без оптимизаций (каждая строка кода → почти такая же инструкция). Удобно для отладки.
* `-O1` — базовые оптимизации (DCE, простые свёртки).
* `-O2` — баланс: почти всё важное включено, но без экстремальных техник. Обычно дефолт для продакшена.
* `-O3` — агрессивные оптимизации (глубокое разворачивание циклов, векторизация, автопараллелизм). Иногда даёт прирост, иногда наоборот ухудшает из-за роста бинарника.
* `-Ofast` — ещё агрессивнее: допускает нарушение стандартов (например, IEEE 754 для float).
* `-Os` — оптимизация по размеру.
* `-Oz` (Clang) — ещё сильнее ужимает код.

---

## 🧩 Специальные техники

* **LTO (Link-Time Optimization)**

  * Оптимизация на этапе линковки, когда компилятор видит сразу весь проект.
  * Может инлайнить функции из других файлов, убирать дубли.
  * Минус: дольше собирается.

* **PGO (Profile-Guided Optimization)**

  * 1-я сборка → бинарь собирает статистику (какие ветки чаще выполняются).
  * 2-я сборка → компилятор учитывает статистику и переставляет код так, чтобы горячие пути были быстрее.

* **Векторизация**

  * Использование SIMD-инструкций (SSE, AVX, Neon).
  * Цикл `for` может превратиться в инструкции, которые обрабатывают сразу 4–8 элементов за раз.

---

## ⚠️ Подводные камни

* Оптимизации могут **сломать отладку** (строки исходника не совпадают с реальными инструкциями).
* При `-O3` иногда производительность падает из-за роста бинарника и кеш-миссах.
* Aggressive float-оптимизации (`-Ofast`, `-ffast-math`) могут ломать точность и порядок вычислений.

# 📌 Общий вид строки компиляции

```bash
g++ [опции] файл.cpp -o программа [опции_линковки]
```

---

# 🔑 Основные опции

### 🎯 Ввод / вывод

* `файл.cpp` — исходный код.
* `-o имя` — имя выходного файла.
  Пример: `-o app` → создаст `./app` (или `app.exe` на Windows).

---

### 🛠️ Режимы компиляции

* `-E` — только препроцессинг (результат — «развёрнутый» исходник).
* `-S` — компиляция до ассемблера (`.s`).
* `-c` — компиляция до объектного файла (`.o`), **без линковки**.
* (по умолчанию) — компиляция + линковка → готовый бинарь.

---

### 📚 Подключение заголовков и библиотек

* `-Iпуть` — добавить путь поиска заголовков (`#include`).
* `-Lпуть` — добавить путь поиска библиотек при линковке.
* `-lname` — подключить библиотеку `libname.so` или `libname.a`.
  Пример: `-lm` подключит `libm` (математическую).

---

### ⚙️ Стандарты

* `-std=c++11` / `-std=c++17` / `-std=c++20` — выбрать стандарт.
* `-pedantic` — строгое соответствие стандарту.
* `-ansi` — эквивалент `-std=c++98 -pedantic`.

---

### 🛡️ Диагностика

* `-Wall` — основные предупреждения.
* `-Wextra` — дополнительные.
* `-Werror` — превращает предупреждения в ошибки.
* `-w` — отключить все предупреждения.

---

### 🚀 Оптимизация

* `-O0` — без оптимизаций (отладка).
* `-O1` — простые оптимизации.
* `-O2` — стандартный уровень (обычно баланс).
* `-O3` — агрессивные оптимизации.
* `-Ofast` — ещё агрессивнее (может нарушать стандарт).
* `-Os` — оптимизация по размеру.
* `-Oz` — сильнее ужимает (только в Clang).

---

### 🐞 Отладка и анализ

* `-g` — добавить отладочную информацию (gdb, lldb).
* `-fsanitize=address` — проверка утечек/ошибок памяти.
* `-fsanitize=undefined` — проверка UB.
* `-pg` — добавить профилирование (gprof).

---

### 🔗 Линковка

* `-static` — статическая линковка (все библиотеки «вшиваются»).
* `-shared` — создать динамическую библиотеку (`.so`).
* `-fPIC` — позиционно-независимый код (для `.so`).
* `-pthread` — добавить поддержку потоков (POSIX Threads).

---

# 📝 Примеры

### 1. Скомпилировать простую программу

```bash
g++ main.cpp -o app
```

### 2. Разбить на объектные файлы и собрать

```bash
g++ -c main.cpp -o main.o
g++ -c utils.cpp -o utils.o
g++ main.o utils.o -o app
```

### 3. Использовать стандарт C++20 и включить предупреждения

```bash
g++ -std=c++20 -Wall -Wextra main.cpp -o app
```

### 4. Оптимизированный билд с отладкой

```bash
g++ -O2 -g -std=c++17 main.cpp -o app
```

### 5. С линковкой внешней библиотеки (например, math)

```bash
g++ main.cpp -o app -lm
```

**исходники + флаги компиляции + флаги линковки**.
