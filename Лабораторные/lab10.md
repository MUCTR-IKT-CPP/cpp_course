### Вариант 1: "Виртуальный склад"

Базовая часть:
Разработать программу для управления виртуальным складом. Основная сущность — Item (товар) с полями: уникальный идентификатор (строка), название (строка), количество на складе (целое число), цена (дробное число).
1.  Создать класс Warehouse, который внутри использует контейнер STL (например, std::map или std::unordered_map) для хранения товаров, где ключ — идентификатор товара.
2.  Реализовать методы:
    *   addItem: Добавить новый товар на склад. Если товар с таким ID уже существует, выбросить стандартное исключение std::invalid_argument.
    *   removeItem: Удалить товар по ID. Если товара не существует, выбросить std::out_of_range.
    *   updateQuantity: Обновить количество товара. Если новое количество отрицательное, выбросить std::invalid_argument. Если товар не найден, выбросить std::out_of_range.
    *   getItemInfo: Получить информацию о товаре. Если товар не найден, выбросить std::out_of_range.
3.  В функции main продемонстрировать работу всех методов, обрабатывая возникающие стандартные исключения с выводом информативных сообщений.

Усложненная часть:
1.  Создать иерархию собственных классов исключений, наследуемых от std::exception:
    *   WarehouseException (базовый класс для всех исключений склада) с виртуальным методом what().
    *   ItemNotFoundError: Выбрасывается, когда товар не найден. Должен содержать ID искомого товара.
    *   InsufficientQuantityError: Выбрасывается при попытке списать со склада больше товара, чем есть. Должен содержать ID товара, запрошенное и текущее количество.
    *   NegativeValueError: Выбрасывается при попытке установить отрицательное значение для количества или цены.
2.  Заменить выброс стандартных исключений в методах класса Warehouse на выброс соответствующих пользовательских исключений.
3.  В функции main создать сценарий, который последовательно вызывает все возможные ошибки, и продемонстрировать их перехват и обработку с выводом детальной информации из пользовательских исключений.

### Вариант 2: "Библиотечный каталог"

Базовая часть:
Создать систему для учета книг в библиотеке. Класс Book содержит: ISBN (строка), название, автор, год издания, статус (доступна/выдана).
1.  Создать класс LibraryCatalog, который хранит коллекцию книг (например, std::vector<std::shared_ptr<Book>>).
2.  Реализовать методы:
    *   addBook: Добавить книгу. Если книга с таким ISBN уже есть, выбросить std::runtime_error.
    *   checkOutBook: Выдать книгу (изменить статус). Если книга не найдена или уже выдана, выбросить std::logic_error.
    *   returnBook: Вернуть книгу. Если книга не найдена или не была выдана, выбросить std::logic_error.
    *   findBook: Найти книгу по ISBN. Если не найдена, выбросить std::out_of_range.
3.  Написать функцию main, которая демонстрирует все сценарии, включая ошибочные, с обработкой исключений.

Усложненная часть:
1.  Создать иерархию исключений:
    *   LibraryException (базовый).
    *   BookNotFoundError: Содержит ISBN.
    *   DuplicateBookError: Содержит ISBN при попытке добавления дубликата.
    *   InvalidBookOperationError: Содержит ISBN и описание операции (например, "попытка вернуть недоступную книгу").
2.  Модифицировать методы LibraryCatalog для использования пользовательских исключений.
3.  Добавить в main сценарий, где обрабатываются разные типы исключений из иерархии, включая перехват по базовому классу LibraryException.

### Вариант 3: "Вектор с дополнительной проверкой"

Базовая часть:
Реализовать класс-обертку SafeVector вокруг std::vector<T>, которая добавляет проверки границ и состояний.
1.  Сделать класс шаблонным.
2.  Реализовать методы at, front, back, pop_back, которые при нарушении предусловий (выход за границы, обращение к пустому вектору) выбрасывают стандартные исключения std::out_of_range или std::logic_error.
3.  Реализовать метод reserve, который при передаче значения, меньшего, чем текущая capacity(), выбрасывает std::invalid_argument.
4.  В main протестировать SafeVector с типом int, целенаправленно вызывая все возможные ошибки и обрабатывая их.

Усложненная часть:
1.  Создать иерархию исключений для SafeVector:
    *   SafeVectorException.
    *   EmptyVectorError: При вызове pop_back, front, back на пустом векторе.
    *   IndexOutOfRangeError: При выходе индекса за границы в методе at. Должен содержать индекс и размер вектора.
    *   InvalidCapacityError: При неверном аргументе в reserve.
2.  Заменить стандартные исключения в методах SafeVector на пользовательские.
3.  Продемонстрировать в main работу с SafeVector<std::string>, показывая, что обработка исключений работает корректно для разных типов данных.

### Вариант 4: "Парсер математических выражений"

Базовая часть:
Создать простой парсер и вычислитель для математических выражений с числами с плавающей точкой, операциями +, -, *, / и скобками.
1.  Реализовать функцию double evaluateExpression(const std::string& expression). Выражение передается в виде строки.
2.  Использовать алгоритм сортировочной станции (Dijkstra's Shunting Yard) или рекурсивный спуск для парсинга.
3.  При обнаружении ошибок (некорректные символы, несбалансированные скобки, неверный синтаксис) выбрасывать std::invalid_argument.
4.  При делении на ноль во время вычислений выбрасывать std::runtime_error.
5.  В main реализовать цикл, где пользователь вводит выражения, а программа выводит результат или обработанное исключение.

Усложненная часть:
1.  Создать иерархию исключений для парсера:
    *   ExpressionParserException.
    *   SyntaxError: Содержит позицию в строке и описание синтаксической ошибки.
    *   DivisionByZeroError: Содержит информацию о выражении, где произошла ошибка.
    *   UnbalancedParenthesesError.
2.  Модифицировать функцию evaluateExpression и вспомогательные функции для выброса этих исключений.
3.  Улучшить обработку в main, чтобы для SyntaxError выводить строку выражения и указатель на место ошибки.

### Вариант 5: "Менеджер задач с приоритетами"

Базовая часть:
Разработать систему управления задачами. Задача (Task) имеет описание, приоритет (целое число) и статус выполнения.
1.  Создать класс TaskManager, который хранит задачи в контейнере, упорядоченном по приоритету (например, std::priority_queue или отсортированный std::vector).
2.  Реализовать методы:
    *   addTask: Добавить задачу. Если задача с идентичным описанием уже существует, выбросить std::runtime_error.
    *   completeTask: Отметить задачу как выполненную (по индексу/итератору). Если индекс неверный или задача уже выполнена, выбросить std::logic_error.
    *   getNextTask: Получить следующую задачу с наивысшим приоритетом. Если список задач пуст, выбросить std::out_of_range.
3.  В main показать добавление, завершение задач и обработку пустого списка.

Усложненная часть:
1.  Создать иерархию исключений:
    *   TaskManagerException.
    *   DuplicateTaskError.
    *   TaskNotFoundError: При попытке завершить несуществующую задачу.
    *   NoTasksError: При запросе следующей задачи из пустого менеджера.
2.  Заменить исключения в TaskManager на пользовательские.
3.  Добавить в main функцию, которая запускает "исполнитель задач": в цикле извлекает и "выполняет" следующую задачу, пока не будет выброшено NoTasksError, которое перехватывается для graceful shutdown.

### Вариант 6: "Кэш данных в памяти"

Базовая часть:
Реализовать простой кэш с временем жизни записей (TTL). Элемент кэша — ключ (строка), значение (строка), время добавления.
1.  Создать класс MemoryCache. Внутри использовать std::unordered_map для хранения данных.
2.  Реализовать методы:
    *   put: Добавить или обновить запись. Если значение — пустая строка, выбросить std::invalid_argument.
    *   get: Получить значение по ключу. Если ключ не найден или TTL истек, выбросить std::out_of_range. (Для проверки TTL использовать фиксированное значение, например, 60 секунд).
    *   remove: Удалить запись по ключу. Если ключа нет, выбросить std::out_of_range.
3.  В main симулировать работу с кэшем, включая ситуации с просроченными данными и пустыми значениями.

Усложненная часть:
1.  Создать иерархию исключений:
    *   CacheException.
    *   InvalidDataError: При попытке сохранить пустое значение.
    *   KeyNotFoundError: Содержит ключ.
    *   CacheExpiredError: Содержит ключ и время истечения.
2.  Модифицировать MemoryCache для использования пользовательских исключений.
3.  Реализовать в main периодическую "очистку" кэша от устаревших записей и продемонстрировать, что при обращении к очищенной записи выбрасывается CacheExpiredError.

### Вариант 7: "Система аутентификации"

### Вариант 8: "Генератор отчетов из CSV"

Базовая часть:
Написать программу, которая читает CSV-файл и строит простой отчет (например, сумму значений в определенном столбце).
1.  Создать функцию readCSV, которая принимает имя файла и номер колонки для анализа. Функция возвращает std::vector<double> значений из этой колонки.
2.  При открытии файла, если файл не существует, ловить и перевыбрасывать исключение std::runtime_error с уточняющим сообщением.
3.  При парсинге строк, если количество колонок в строке не соответствует ожидаемому, или значение в целевой колонке не может быть преобразовано в число, выбрасывать std::invalid_argument.
4.  В main обрабатывать исключения, выводя понятные сообщения об ошибках (файл, строка).

Усложненная часть:
1.  Создать иерархию исключений:
    *   CSVException.
    *   FileOpenError: Содержит имя файла.
    *   ParsingError: Содержит номер строки, содержание строки и описание ошибки.
    *   InvalidColumnError: Содержит номер колонки и их реальное количество в строке.
2.  Модифицировать функцию readCSV и вспомогательные функции для выброса этих исключений.
3.  В main добавить обработку разных типов исключений, для ParsingError выводить детальную информацию о проблемной строке. Реализовать функцию, которая вычисляет и выводит отчет, обрабатывая возможные ошибки на всех этапах.
